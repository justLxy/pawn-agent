# 当铺代理人（AI 当铺人生）

《当铺代理人》是一款**模拟经营类纯文字网页游戏**。玩家扮演当铺掌柜，通过接待顾客、鉴定物品、讨价还价、修复转卖、升级店铺，在 AI 与规则引擎共同驱动的经济系统中积累财富与声誉。

本作在保留《当铺人生》式核心经济循环的同时，将**物品、顾客、对话、谈判、鉴定/修复叙事、随机事件**尽可能交给大模型实时生成；未配置 AI 或接口超时时，由本地占位与算法兜底，保证可完整游玩——配置 AI 后，系统还会在**谈价、读档、叫下一位**时后台补货，尽量让队列里始终是稀奇古怪的 AI 货。

- **想玩懂游戏**：从下方 [游戏目标](#游戏目标) 起依次阅读。
- **想本地跑起来**：直接看 [快速开始](#快速开始) 与 [AI 配置与兜底策略](#ai-配置与兜底策略)。

## 核心特色

| 能力 | 说明 |
|------|------|
| 纯文字经营 | 对话、旁白、物品故事是主体验；UI 负责氛围与操作引导 |
| AI 无限内容 | 顾客人设、**稀奇物品名与故事**、谈判台词、事件分支、鉴定/修复说明可由模型生成；物品名不与近期库存/队列重复 |
| 流水线补货 | 谈价、成交、读档时后台生成 AI 卖家，替换队列中的本地占位顾客 |
| 双角色顾客 | 既有**卖家上门**（你收购），也有**买家上门**（你出售库存） |
| 自然语言谈判 | 支持自由输入；服务端规则引擎裁决成交、让步与离场，AI 只负责人物化表达 |
| 流式谈判 | 前端默认走 `/api/negotiate/stream`，逐字显示顾客回复 |
| 完整物品链路 | 收购 → 鉴定 → 修复 → 展示 → 系统出售 / 卖给上门买家 / 挂玩家市场 |
| 宏观经济 | 经济指数、通胀压力、分类市场趋势、库存持有成本与时间价值 |
| 顾客关系 | 回头客、满意度、关系等级、引荐与图鉴记录 |
| 云端存档 | 注册登录后由服务器权威持久化；支持读取与重开，不接受客户端覆盖 |
| 玩家市场 | 全服挂单买卖、橱窗参观、交易税与排行榜 |
| 成就系统 | 经营、交易、声誉、收藏、技能等多类成就与奖励 |
| 离线可玩 | 无 API Key 时用本地程序化物品名 + 规则兜底；有 Key 时本地占位会被后台 AI 逐步替换 |

## 快速开始

### 环境要求

- Python 3.10+
- Node.js 18+

### 1. 配置环境变量

在项目根目录或 `backend/` 下创建 `.env`：

```env
# 必填：启用 AI 生成（稀奇物品、顾客故事、谈判台词；不填则本地占位，玩法仍完整）
QWEN_API_KEY=你的_API_Key

# 可选
QWEN_API_URL=https://ws-nl8tvztfpss60i8t.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/chat/completions
QWEN_MODEL=qwen3.5-flash

# 可选：数据库路径、CORS
PAWNSHOP_DB_PATH=backend/pawnshop_online.db
CORS_ALLOWED_ORIGINS=http://localhost:5173,https://game.lvxy.cc
```

前端可选（`frontend/.env`）：

```env
VITE_API_BASE_URL=http://localhost:8000
```

### 2. 启动后端

```bash
cd backend
pip install -r requirements.txt
python app.py
```

默认监听 `http://127.0.0.1:8000`，启动时自动 `init_db()`。

### 3. 启动前端

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`，注册账号并创建当铺名称即可开局。

### 4. 生产构建

```bash
cd frontend && npm run build
# 将 dist/ 静态资源部署到 CDN 或 Nginx，并保证 API 指向后端
```

## 游戏目标

本作是**开放式经营**，没有强制 Game Over：你可以一直玩下去，用资产、声誉、成就和排行榜衡量进度。

长期目标包括：

- 把当铺从街边小店升到 **Lv.8 当铺祖师**
- 维持正现金流，扛住工资、税费、持有成本与突发事件
- 建立**高声誉 + 回头客网络**，让每日客流更稳定
- 在全服排行榜上竞争资产、利润或收藏分
- 完成成就、填满图鉴，体验 AI 生成的稀有传奇货

核心技巧只有一句：**低买高卖，且尽量在信息充分时交易**——鉴定、谈判、关系与宏观经济都会改变「低买」和「高卖」的边界。

## 新手第一天

1. **注册并起名**：用户名 + 密码 + 当铺名称；系统赠送 **$10,000** 现金，第 1 天自动开门。
2. **进「大堂柜台」**：第一位顾客已在场。先看顶栏是 **收购** 还是 **出售**，再看右侧大字报价。
3. **收购（卖家上门）**：先点「鉴定」或聊天问来历；用试探价压价；满意后点「成交」。现金会减少，货进仓库。
4. **出售（买家上门）**：对方盯着你库里某件货。尽量把出价往上谈；成交后货离开库存，现金增加。
5. **送走顾客**：成交或拒绝后，点「送离 / 下一位」直到今日队列清空。
6. **整理仓库**：去「仓库藏品」看新货；贵的可先 **展示** 或 **鉴定**；破损且非 Mint 的可考虑 **修复**。
7. **营业结算**：回大堂点「营业结算」，查看工资、运营成本、库存持有费等明细。
8. **随机事件**：若弹出事件，阅读两个选项的 **效果说明** 再选；有的会收钱/扣钱，有的会送一件货进仓库。
9. **开启下一天**：处理完事件后点「开启第 N 天」。有 AI 时优先使用**营业结算后后台锁定的明日预生成**（点击时最多等待约 22 秒，超时即用本地兜底秒开，不现场整批生成）；游玩中也会持续后台预热。

前期建议：不要一上来就贷款囤满货；先完成几笔稳妥交易，把 **鉴定室** 或 **商业技能** 养起来。

## 每日经营流程

### 今日客流怎么算

```
基础顾客数 = max(2, 2 + 当铺等级 + 店面设施等级÷2)
若雇了宣传员：再 +1～2 人（随机）
```

例：Lv.1 当铺、店面 Lv.1、无宣传员 → 至少 **3** 位顾客。

### 一天的时间线

```
开门 → 顾客1 → 顾客2 → … → 队列空 → 营业结算 → [随机事件] → 下一天
         ↑ 谈价期间后台可能把队列里的占位换成 AI 新货
```

- 每位顾客处理完要 **送离**，才会叫下一位。
- **营业结算后**不能继续谈判；必须先处理事件（若有），再「开启下一天」。
- 修复中的物品在 **日终**推进天数；完工消息写在结算日志里。
- 配置 AI 后，**不必等整队生成完才开门**：第一位顾客就绪即可开谈，其余在后台陆续到位。

### AI 顾客与物品怎么来

游戏采用 **「先 1 后 N + 后台补货 + 明日预生成」** 三层机制，尽量让你随时见到 AI 稀奇货，又不必在门口干等：

```
开门 / 下一天
  ├─ 新账号注册：给 AI 约 9 秒抢跑窗口，超时立即本地占位秒开门
  ├─ 第 1 位顾客：优先 AI 生成，立即可谈
  ├─ 其余顾客：并行 AI 生成；单个失败只影响该位，不拖垮全天
  └─ 整队生成上限 180 秒（仅后台兜底上限）；有部分结果也会先开门

谈价 / 成交 / 读档 / 叫下一位
  └─ 后台「队列补货」：用 AI 卖家替换队列里 generation_source=local 的占位

当日任意操作后
  └─ 后台「明日预生成」：游玩中持续预热；**营业结算后强制锁定** day+1 整队顾客，下一天秒开
```

| 情况 | 实际表现 |
|------|----------|
| **有 API Key，网络正常** | 卖家上门货多为 AI 生成；名字、描述、故事各不相同，可很离谱 |
| **AI 单客超时** | 该位暂用本地程序化占位；后台补货会再换成 AI |
| **无 Key 或全天 AI 失败** | 全天用本地程序化物品 + 规则顾客，玩法完整，文本重复度更高 |
| **买家上门** | 物品来自**你库存里已有的一件**，不是新生成；旧货名字不会变 |

**卖家比例**：约 **62%** 顾客为卖家上门（余下为买家，前提是你库里有可售货）。

**当前正在谈的顾客不会被后台替换**，避免谈一半换人换货。

## 收购与出售：两种核心模式

这是全书最重要的机制差异——**同一套对话，胜负方向相反**。

| | **收购**（顾客 = 卖家） | **出售**（顾客 = 买家） |
|---|------------------------|-------------------------|
| 对方拿什么 | 一件来路货（可能赝品） | 你库存里的指定一件 |
| 你的钱 | 流出（你付款） | 流入（对方付款） |
| 顶栏标签 | 收购 · **对方要价** | 出售 · **对方出价** |
| 你的目标 | 成交价 **越低**越好 | 成交价 **越高**越好 |
| 谈判时 | 你应 **压价** | 你应 **抬价** |
| 成交后 | 物品进仓库 | 物品出库、进已售记录 |

### 买家从哪来

- 仅当你仓库里有 **可售** 物品（在库或展示中）时，才可能刷买家。
- 每日约 **38%** 顾客为买家（约 62% 为卖家上门）；系统会把买家 **分配到不同库存件**，优先盯 **展示柜** 里的货。
- 若你谈判期间把买家目标 **系统出售** 掉，对方会改看别的货，或离开。

### 卖家与赝品

- 新上门卖家的物品名、描述、故事由 **AI 或本地程序化组合** 生成；`ITEM_TEMPLATES` 仅在后端用作**定价骨架**（价值区间、赝品率），不再直接作为玩家看到的固定货名。
- 模板物品带 **赝品率**；欺诈型顾客更可能带假货。
- 赝品的 `actual_value` 会远低于叫价；卖家（尤其欺诈型）在话术里仍可能吹得很高。
- **不鉴定就收购** = 博彩；鉴定识破后顾客会有情绪反应，可趁机压价。

## 顾客性格与关系系统

### 五种性格

| 性格 | 谈判特点 | 应对建议 |
|------|----------|----------|
| **强硬** | 底线高，让步慢；低价易掉耐心 | 用鉴定结果、行情证据谈；别空口压价 |
| **急切** | 易让步，想快成交 | 可大胆开低价（收购）或坚持略高价（出售） |
| **犹豫** | 需要安抚和解释 | 多聊来历、保值；魅力技能有帮助 |
| **欺诈** | 可能售假；被戳穿会心虚 | 务必鉴定；追问细节 |
| **专家** | 懂行，对价敏感 | 少忽悠，用专业话术 |

### 耐心值

- 初始约 **5～7**（受性格、店面、宣传员、魅力、熟客等影响）。
- 谈判中报价太离谱会 **扣耐心**；聊得好可能回升（魅力高时）。
- **耐心 ≤ 0**：顾客 **walk_out**，本单失败；有概率 **声誉 -1**。
- 顶栏始终显示当前耐心，旁白也会提示变化。

### 关系等级

由 **满意度** 与 **来访次数** 共同决定：

| 等级 | 大致条件 | 好处 |
|------|----------|------|
| 新客 | 默认 | — |
| 熟客 | 满意 ≥58 或来访 ≥2 | 耐心 +1，报价略有利 |
| 忠实 | 满意 ≥76 且来访 ≥3 | 收购时更易让步 |
| 贵宾 | 满意 ≥88 且来访 ≥3 | 同上，更明显 |
| 关系紧张 | 满意 ≤28 | 更难谈 |

**满意度变化（示例）**：成交 +12～14；拒绝 -8；谈崩离场 -14；识破欺诈 -22。

### 回头客与引荐

- 满意的老客有概率 **顶替** 当日队列中的某位新客，带着上次的记忆和 `last_deal_summary` 再来。
- **忠实 / 贵宾** 还可能 **引荐** 新顾客（新脸孔，但带着推荐关系），提高声誉与成就进度。

## 谈判系统详解

### 你可以说什么

游戏会解析你的中文输入，识别：

| 意图 | 典型说法 | 效果 |
|------|----------|------|
| **报价** | 「我出 5000」「给你八千」 | 提取数字，进入比价 |
| **说服** | 「这行行情不好」「店里也要担风险」 | 顾客可能小幅让步 |
| **追问** | 「哪来的」「保真吗」 | 顾客解释来历（AI 编故事） |
| **接受** | 「成交」「就这个价」 | 按当前报价或你报的价成交 |
| **拒绝** | 「不卖」「算了」 | 结束谈判 |

支持 **阿拉伯数字**（含千分位逗号）和简单 **中文数字**（如「三千五」）。

### AI 裁决（真正的胜负手）

配置大模型后，**能不能成交、新报价多少、耐心变化** 均由 AI 顾客根据人设、`limit_price`（心理底线/上限参考）、当前报价、你的发言与技能等级 **自行决定**，不再用后端固定比例公式覆盖。

**收购（对方是卖家）**

- 顾客心里有 **底线价** `limit_price`（仅 AI 知晓，用于判断让步幅度）。
- 是否成交、要价降到多少，由 AI 结合性格（强硬/急切等）与你说服力判断。

**出售（对方是买家）**

- 买家有 **上限价** `limit_price` 作参考。
- 是否成交、出价抬到多少，同样由 AI 决定。

技能 **谈判 + 魅力**、调查证据、重复话术、关系记忆和历史让步都会进入服务端决策引擎。AI 只把已经确定的结果写成符合人物性格的台词；未配置 API 时仍使用相同的博弈规则。

> **注意**：每位顾客都有一个 **隐藏的保留价扰动**（约 ±6%，熟客更小），你算不出精确的"最低可接受价"，一味压到极限价有翻车风险。同一套 **证据/说辞反复刷** 收益会快速递减——谈判是博弈，不是背模板。

### 旁白与顶栏价格

- 顶栏 **始终显示** `current_offer`——谈完后点「成交」即按此价。
- 报价变动时，对话区上方会出现旁白：「对方将要价 **降至** $X」或「对方将出价 **抬至** $X」（根据涨跌自动用字）。

### 快捷按钮（生成话术，非自动成交）

| 按钮 | 收购时 | 出售时 |
|------|--------|--------|
| **试探价** | 结合对方已降价幅度，生成偏低报价话术 | 结合对方已加价幅度，生成偏高要价话术 |
| **当前价** | 按当前要价的比例生成 | 同上 |
| **强势报价** | 更激进的压价话术 | 更激进的抬价话术 |

需 **自己点发送** 才会提交谈判。

### 大堂操作

| 按钮 | 作用 |
|------|------|
| 鉴定 | 付鉴定费，揭示区间与真伪（仅本单货物，每单一次） |
| 成交 | 按顶栏 `current_offer` 成交 |
| 拒绝 | 顾客离开，可能损满意度 / 声誉 |
| 送离 | 本单已结束后叫下一位 |

### 流式对话

默认使用流式 API：顾客回复会 **逐字出现**；价格与耐心在流结束后已确定，与文字同步写入状态。

## 鉴定系统详解

### 何时鉴定

| 场景 | 位置 | 说明 |
|------|------|------|
| 谈判中 | 大堂 · 鉴定 | 针对 **当前顾客带来的货**；鉴定后顾客会反应 |
| 已入库 | 仓库 · 鉴定 | 针对库存；每件货 **只能鉴定一次** |

### 三种方法

| 方法 | 费用系数 | 赝品识破 | 估值误差 | 适合 |
|------|----------|----------|----------|------|
| 目测初鉴 | ×0.8 | 较低 | ±大 | 便宜货、试水 |
| 标准鉴定 | ×1.45 | 中 | ±中 | 日常 |
| 深度鉴定 | ×3.2 | 高 | ±小 | 高价货、可疑货 |

**费用** ≈ `max(120, 市值×8%×经济指数×方法系数×(1-折扣))`  
折扣来自：鉴定室等级、雇佣鉴定师（最高约 45% 折扣）。

### 鉴定结果

- **真伪**：若为赝品，按「识破率」掷骰；成功则 `发现明显作伪`，失败则仍可能看走眼。
- **估值区间** `appraised_value_low ~ high`：围绕 **真实价值** `actual_value` 波动，不是围绕顾客叫价。
- **鉴定笔记**：多条文字说明；有 AI 时由模型生成，否则用模板条目。
- **技能经验**：鉴定成功加鉴定技能 XP。

### 玩家看不到的隐藏信息

- `actual_value`：真实价值，**鉴定前不显示**。
- 内部市值：由服务器维护并随日子波动；玩家通过鉴定区间和操作预览判断，不直接获得精确底数。
- 收购决策应对比：**成交价 vs 鉴定区间 vs 未来修复/持有成本**。

## 物品属性与库存管理

### 五大分类

流行文化、艺术、珠宝钟表、古董、历史遗物——每类有独立 **市场趋势系数**（每日波动），影响新货估值和库存日终涨跌。

AI 生成时鼓励天马行空、避免常见套路，仅与**近期已出现物品名**去重；不会把内置模板库里的固定品名喂给模型。本地兜底则用形容词 + 年代 + 物件的程序化组合（如「来历不明的冷战时期街机摇杆」）。

### 稀有度

| 稀有度 | 价值倍率 | 持有成本率 | 说明 |
|--------|----------|------------|------|
| 普通 | ×1.0 | 低 | 量大价稳 |
| 稀有 | ×1.6 | 中 | 适合中期持有 |
| 史诗 | ×2.6 | 中高 | 高利润高风险 |
| 传奇 | ×4.2 | 高 | 镇店之宝级 |

### 成色

| 成色 | 英文 | 说明 |
|------|------|------|
| 较差 | Poor | 收购模板价最低；修复潜力大 |
| 良好 | Good | 中间档 |
| 完好 | Mint | 最高档；**不可再修复** |

### 物品状态

| 状态 | 你能做什么 |
|------|------------|
| 在库 `stored` | 鉴定、修复、展示、系统出售、挂市场 |
| 展示 `displayed` | 同上；吸引买家；系统出售有加成 |
| 修复中 `repairing` | 不能卖不能展示；日终推进 |
| 已售 `sold` | 仅历史记录 |
| 挂单 `listed` | 在玩家市场，不在本地仓库 |

### 时间价值与持有成本（日终）

每件在库/展示/修复中的货，每天结算时：

1. **市值波动**：受稀有度、成色、是否展示、是否修复中、分类市场趋势、经济指数等影响，单日涨跌通常 capped 在约 -3.5%～+3.2%。
2. **持有成本**：按市值和稀有度扣现金；展示中略高；安全设施、商业技能可减轻。

长期囤贵货要算：**涨价的期望值 vs 每日持有费**。

## 修复与展示柜

### 修复流程

1. 在仓库选 **非 Mint** 且未在修的物品 → 选方案 → 付修理费 → 进入修复中。
2. **天数** ≈ `修复难度 - 工坊等级÷2 + 方案修正`；雇修复师有概率 **每天多推进 1 天**。
3. **日终**判定成功：成功率与修复技能、工坊、方案、是否雇修复师相关。
4. **成功**：成色升一级（Poor→Good→Mint），真实价值与市值跳涨（Good 约 +45%/+35%，Mint 更高）。
5. **失败**：真实价值与市值均下调约 8~10%，仍回到在库；且有约 **28% 概率修坏一档成色**（Mint→Good、Good→Poor），价值明显受损。所以贵货修复是真正的赌注，不再"修了必赚"。

| 方案 | 费用 | 天数 | 成功率加成 |
|------|------|------|------------|
| 保守 | ×0.85 | +1 天 | +10% |
| 标准 | ×1.0 | 标准 | — |
| 高阶 | ×1.55 | -1 天 | +14% |

### 展示柜

- **容量** = `2 + 展示柜等级×2`（例：Lv.3 展示柜 → 8 件）。
- 展示中的货：
  - 每日市值有 **额外正向漂移**；
  - **系统出售** 时售价 +4%×展示柜等级；
  - 更容易被 **上门买家** 选中。
- 可设 **橱窗售价**（联机）：其他玩家参观时可买，价格需在参考价 30%～300% 之间。

## 赚钱与出货渠道

按「控制力 / 潜在利润」排序：

| 渠道 | 操作 | 利润特点 |
|------|------|----------|
| **1. 收购 → 修复 → 系统出售** | 低买 → 修好 → 仓库点系统出售 | 稳定；利润取决于买入价与成色提升 |
| **2. 收购 → 展示 → 等买家** | 摆柜 → 出买家时谈判抬价 | 可能高于系统价；占展示位 |
| **3. 收购 → 持有等涨跌** | 赌分类市场趋势 + 经济指数 | 有风险；持有费持续扣 |
| **4. 玩家市场** | 挂单 → 他人购买 | 价由你定；成交扣 **5% 税**；24h 内不能反复刷同一货 |
| **5. 上门买家成交** | 买家盯货谈判 | 无需挂单；价由谈判决定 |

### 系统出售公式（即时变现）

```
售价 = 市值 × (0.72～0.92 随机 + 商业技能×2.5% + 展示加成 + 稀有度加成)
```

- 展示加成：在展时 +4%×展示柜等级。
- 稀有度加成：稀有 +6%，史诗 +12%，传奇 +20%。
- 适合 **快进快出** 或现金流紧张时清仓。
- **反套利**：刚从玩家市场／同业铺子购入的货，**24 小时内系统出售不给正差价**（最多按购入价回本），杜绝"低价扫货→秒卖差价"的无风险刷钱。散客上门收来的货不受此限。

### 典型一单利润（收购）

```
利润 ≈ 最终卖出价 - 收购价 - 鉴定费 - 修复费 - 持有成本分摊
```

## 经济系统与每日成本

### 开局与宏观

| 项目 | 数值 / 说明 |
|------|-------------|
| 初始现金 | $10,000 |
| 经济指数 | 0.72～1.85，每日微变；影响成本、贷款、估值 |
| 压力标签 | 通胀 / 通缩 / 平稳，影响叙事与部分波动 |
| 分类市场 | 五大类各一个系数，每日刷新 |

### 日终账单（营业结算里可见）

| 项目 | 说明 |
|------|------|
| 员工工资 | 已雇员工日薪之和 × 经济指数 |
| 运营成本 | 基础约 `260 + 等级×90 + 设施总和×18`，商业技能最多减约 25% |
| 贷款利息 | 本金 ×（基础 2% + 通胀相关修正），有贷必扣 |
| 营业税 | 每 **7** 天；按 **当日现金增值部分** ×（约 8% + 经济修正） |
| 库存持有成本 | 见上文；从现金直接扣 |
| 修复完工 | 日志条目，非额外扣费 |

### 贷款（经营财务页）

- **额度** ≈ `(20000 + 等级×8000) × 经济指数`，有下限。
- **借款** 即时到账；**还款** 任意金额，不超过本金。
- 适合扩库存或应急，但利息是永久压力。
- **现金流告急兜底**：日终若现金为负，银行自动启用周转授信把现金补到 500 并计入贷款——不会强制 Game Over，但**连续告急会递增代价**：声誉逐日多扣（最多 -5/天），连续 2 天起**授信利率逐级上调**（最高 8%/日）。恢复偿付能力后计数清零。别把自动授信当免费提款机。

### 当铺等级

升级费用会随 **经济指数** 浮动；同时设有 **最低经营天数**，避免前期资金充裕时一日冲满级。

| 等级 | 升级费（约，×经济指数） | 最低天数 | 解锁效果（描述） |
|------|-------------------------|----------|------------------|
| Lv.2 | $12,000 | 第 8 天 | 客流增加；更多中高级货 |
| Lv.3 | $38,000 | 第 20 天 | 客流大增；高价值艺术卖家 |
| Lv.4 | $95,000 | 第 38 天 | 拍卖行信息；顾客质量提升 |
| Lv.5 | $260,000 | 第 65 天 | 极高声誉；神级传说遗物 |
| Lv.6 | $850,000 | 第 110 天 | 稀世珍品出现率提升；高端回头客增多 |
| Lv.7 | $1,650,000 | 第 160 天 | 全球珍品渠道；顶级买家 |
| Lv.8 | $3,200,000 | 第 220 天 | 传奇遗物定向流入；当铺祖师 |

## 技能、设施与员工

### 技能（1～10 级）

升级：积累经验 XP。每级所需经验随等级递增（约 `80 + 等级×145 + 等级²×22`），且日常获取的经验会按 **62%** 折算入账，避免数日刷满全部技能。单项技能从 1 级练到 10 级，正常经营大约需要 **数十个游戏日**。

| 技能 | 主要影响 |
|------|----------|
| **谈判** | 可接受价区间；成交 XP |
| **鉴定** | 识破率、误差带、鉴定费效率 |
| **修复** | 费用、成功率、完工 XP |
| **魅力** | 顾客初始耐心、耐心恢复、回头客概率 |
| **商业** | 运营成本折扣、系统出售价 |

### 设施（1～8 级）

升级费随等级递增；**6 级及以上**进入高阶造价区间，且需达到对应 **最低经营天数**（如 Lv.6 需第 105 天）。满级八项设施需更长周期投入。

| 设施 | 作用 |
|------|------|
| 展示柜 | 容量；展示售价；买家偏好 |
| 安全系统 | 盗窃/纠纷类事件损失减免 |
| 鉴定室 | 鉴定费折扣；质量 |
| 修复工坊 | 修理费折扣；成功率 |
| 店面 | 客流；稀有货权重 |

### 员工（雇佣一次性 + 日薪）

| 员工 | 雇佣费 | 日薪 | 作用 |
|------|--------|------|------|
| 鉴定师 | $800 | $100 | 鉴定折扣大；+识破 |
| 修复师 | $1000 | $120 | 修复加速；-25% 修理费；降失败 |
| 宣传员 | $600 | $80 | +1～2 客流；+稀有权重；+引荐率 |

## 随机事件

### 触发

- 每次 **营业结算** 末，约 **62%** 出事件。
- 若连续 **1** 天没事件，下一天 **必出**。

### 玩法

- 屏幕出现 **标题 + 故事 + 两个选项**；每项有 **效果摘要**（现金、声誉、技能、市场等）。
- 选后立刻改状态；须处理完才能 **下一天**。
- 有 AI 时，事件全文可替换为 AI 生成，但 **选项结构** 仍带数值后果。

### 本地事件类型（12 种）

夜间异响、可疑典当、名人来访、市场风向、来源质疑、员工争执、巷口传闻、修复师来信、鉴定讲座、银行授信、老客介绍、暴雨压街等。

### 收货选项

部分选项带 **收进仓库**（`acquire_item`）：按市价一定比例（如「七成」≈ 70%）扣款；钱不够则收失败。AI 事件也可能生成带物品的典当/收购剧情。

### 设施联动

例如「加强安保」类选项：安全等级、保安在岗会降低现金损失。

## 全服市场、橱窗与排行榜

### 玩家市场

1. 在 **仓库** 对货物 **挂售**，标价须在参考价 **30%～300%**。
2. 摊位上限随当铺等级提升（最高约 **45** 单）。
3. 他人购买后：你收 **成交价 - 5% 税**；货进入买家仓库。
4. 从市场买进的货 **24 小时内不能再挂售**（防刷）。

### 橱窗（参观当铺）

- 在 **全服排行** 点某玩家 → 参观其 **展示柜**。
- 仅 **已标价** 的展示品可买；你付标价，对方收税后到账。
- 自己的展示品在仓库设 **橱窗售价** 即可；不标价则只展示不卖。

### 排行榜

| 榜单 | 计分大致方式 |
|------|--------------|
| 资产 | 现金 + 库存市值 |
| 声誉 | 声誉 + 交易成功率 + 好评率等复合 |
| 利润 | 累计总利润 |
| 收藏 | 库存稀有度加权 |

排行榜按 28 天赛季内的资产、声誉、盈利或收藏增长排名。每日保存四类快照，资产榜前 100 名获得排名奖励；第 1 名可得「全服第一当铺」徽章。

## 进阶策略与常见误区

### 推荐策略

1. **先鉴定再大价收**：尤其史诗以上、欺诈性格、来路含糊的货。
2. **急售用系统出售，慢售用展示 + 买家**：高稀有放展示等上门谈。
3. **修复 Poor/Good 的中高市值货**：Mint 不必修；修复费要在预期涨幅里扣除。
4. **关注分类市场趋势**：日终日志和财务页可看；顺势囤货类。
5. **维护熟客**：少拒绝、少谈崩；长期客流和引荐更划算。
6. **中期雇鉴定师 + 升鉴定室**：降低「买假」灭顶风险。
7. **现金紧时减库存**：持有费按市值比例天天扣。

### 常见误区

| 误区 | 事实 |
|------|------|
| 「顶栏价和对话里价不一样」 | 以 **顶栏 current_offer** 为准；对话是叙事，旁白才同步系统价 |
| 「收购时出价越高越好」 | 收购是你付钱，要 **压低** 对方要价 |
| 「不鉴定也能看真实价值」 | 真实值和内部市值都不直接公开，应结合调查、鉴定区间与行情判断 |
| 「营业结算后还能谈」 | 已打烊，须先事件再下一天 |
| 「市场挂单没有成本」 | 成交扣 5% 税；还有 24h 转售限制 |
| 「买家一定会买走展示货」 | 买家可能改目标；你也可以先系统卖掉 |
| 「怎么又是同一件模板货」 | 新卖家货应为 AI/程序化新名；**买家**买的是库存旧货；改代码前的存档货名不会自动变 |
| 「谈价时能不能预生成下一位」 | 可以：每次保存状态会触发**队列补货**与**明日预生成**，下一位在后台生成 |

## AI 配置与兜底策略

### 调用场景

| 场景 | 方法 / 机制 |
|------|-------------|
| 开门 / 下一天 | `async_initialize_day`：先 1 后 N 并行生成；`async_initialize_day_with_fallback` |
| 队列补货 | `generate_ai_seller_customer` + `apply_queue_refill`（`app.py` 后台任务） |
| 明日预生成 | `generate_next_day_prewarm`（每次 `commit_state` 调度） |
| 顾客人设 | `generate_customer_profile` |
| 开场白 | `generate_customer_greeting` |
| 谈判 | `generate_negotiation` / `stream_negotiation_dialogue` |
| 鉴定/修复/拒绝告别 | 对应 `generate_*` |
| 随机事件 | `generate_random_event`；涉及收货时 `generate_deep_item` |
| 深度物品 | `generate_deep_item` / `generate_item_details`（含去重与「稀奇货」prompt） |

### 生成流水线（开发者向）

```
玩家操作 → commit_state
  ├─ apply_pending_queue_refill   # 注入已完成的 AI 补货
  ├─ schedule_queue_refill        # 队列仍有 local 占位则后台生成
  └─ schedule_next_day_prewarm    # 为 day+1 预生成整队顾客

Customer.generation_source
  ├─ ai      模型完整生成
  ├─ prewarm 来自明日预生成缓存
  └─ local   占位（优先被 queue_refill 替换）
```

### 超时与兜底

| 参数 | 值 | 含义 |
|------|-----|------|
| `AI_CUSTOMER_GENERATION_TIMEOUT` | 60s | 单客 AI 生成上限 |
| `AI_DAY_GENERATION_TIMEOUT` | 180s | 整队生成总上限（仅作后台兜底上限，玩家不会现场干等这么久） |
| 注册开局 AI 抢跑窗口 | 9s | 新账号注册最多等 9 秒 AI；超时立即本地占位秒开门，其余 AI 货后台补上 |
| `NEXT_DAY_PREWARM_WAIT` | 22s | 点「开启下一天」时最多等待在途预热；超时走本地兜底秒开 |
| 前端请求超时 | 90s | 客户端兜底，避免后端异常时界面无限 loading |
| `SELLER_CUSTOMER_RATIO` | 0.62 | 有库存时卖家上门概率 |

- **单客超时**：该位暂用 `local` 占位；若已配置 Key，队列补货会再换 AI。
- **全天超时但有部分队列**：`fallback: partial`，仍开门；明日预生成也会缓存部分结果。
- **完全失败或无 Key**：`initialize_day_fast` 本地占位；有 Key 时后续仍可被补货替换。
- **谈判**：`negotiation_engine.py` 维护保留价、急迫度、信任、策略、耐心和历史让步，并确定经济结果；AI 仅生成或流式润色台词。

`ITEM_TEMPLATES` 仍保留于后端，仅用于**价值区间、赝品率、经济锚点**；玩家可见物品名由 AI 或 `LOCAL_ITEM_*` 程序化组合决定，模板里的固定品名不会传给 AI。

### 报价解析

`ai_client` 与前端共用类似正则，从「出/给/卖/要/报价…」后提取数字（支持千分位逗号）。

### 玩家市场活力（服务端，Railway 零命令）

低在线阶段由后台维护一批**拟真玩家当铺**（库内标记 `is_system_player`，仅用于禁止登录/找回密码，**不**暴露给前端），在全服市场挂单、调价、橱窗陈列，并**正常出现在排行榜与在线人数**中，与真人无异。

**部署到 Railway 后无需执行额外脚本**：服务 `startup` 时会自动补全 NPC 与挂单、执行一次市场 tick，并每 6 小时周期性维护。

| 环境变量 | 默认 | 说明 |
|----------|------|------|
| `NPC_MARKET_ENABLED` | `1` | 启用 NPC 市场（设为 `0` 可关闭） |
| `NPC_MARKET_AUTO_SEED` | `1` | 启动时自动补全 NPC 与挂单 |
| `NPC_MARKET_STARTUP_TICK` | `1` | 启动时立即跑一轮维护 |
| `NPC_MARKET_TICK_HOURS` | `6` | 周期 tick 间隔（小时） |
| `NPC_SHOP_COUNT` | `6` | NPC 当铺数量 |

本地调试可选脚本（**生产不必**）：`python scripts/seed_npc_shops.py`、`python scripts/npc_market_tick.py`。

## 开发与扩展

### 状态单一数据源

所有玩法应写入 `GameStateManager`，经 `to_dict()` / `from_dict()` 序列化。关键数值（现金、报价、物品字段）须由后端计算，AI 只补充叙事文本。

### 扩展新玩法时建议

1. 在 `game_state.py` 增加方法与状态字段。
2. 在 `app.py` 暴露 API，返回 `{ result, state }` 统一格式。
3. 在 `App.tsx` 增加操作入口与类型定义。
4. 若需 AI，在 `ai_client.py` 增加 prompt，并保留本地 fallback。

### 本地测试

```bash
# 报价提取
python test_extract.py

# 鉴定 API（需后端运行）
python frontend/test_appraise.py
```

### 注意事项

- `.env` 含密钥，勿提交版本库（已在 `.gitignore`）。
- 修改 `game_state.py` 后注意旧存档兼容性；`Customer.from_dict` 会校正开场白，并为旧存档补默认 `generation_source`。
- 扩展 AI 生成逻辑时，优先改 `ai_client.py` prompt 与 `game_state.py` 的 `_resolve_item_identity` / 队列补货，保留 `ITEM_TEMPLATES` 作经济锚点即可。
- CORS 默认允许 `localhost:5173` 与 `https://game.lvxy.cc`，部署时按需修改。
